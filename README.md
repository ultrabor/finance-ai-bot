# Finance AI Bot

Сервис учёта семейных расходов. Член семьи пишет боту в Telegram «кофе 350» — ИИ-агент сам определяет сумму, категорию и дату и сохраняет трату. Глава семьи видит и редактирует траты всех в веб-панели.

Задание: [docs/test-task-expenses.md](docs/test-task-expenses.md) · паспорт проекта: [docs/PROJECT_PASSPORT.md](docs/PROJECT_PASSPORT.md) · REST API: [api/openapi.yaml](api/openapi.yaml)

**Содержание:** [Запуск](#запуск-за-5-минут) · [Как проверить](#как-проверить) · [Если что-то не работает](#если-что-то-не-работает) · [Автотесты](#автотесты) · [Архитектура](#архитектура) · [Допущения](#допущения)

## Запуск за 5 минут

Нужны Docker с Compose v2, аккаунт Telegram и доступ к LLM. Go и Node.js для запуска не нужны — всё собирается в контейнерах.

### 1. Получить токен бота

В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username. Скопируйте токен вида `123456789:AA...`.

### 2. Узнать свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — он ответит числом вроде `5025107069`. Бот отвечает только ID из белого списка.

### 3. Выбрать LLM

Подойдёт любой провайдер с OpenAI-совместимым `/chat/completions` и поддержкой tool calling:

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` | Комментарий |
|---|---|---|---|
| Groq | `https://api.groq.com/openai/v1` | `openai/gpt-oss-120b` | есть бесплатный тариф, ключ — на [console.groq.com](https://console.groq.com/keys) |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` | |
| OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-haiku-4.5` | |
| Ollama (локально) | `http://host.docker.internal:11434/v1` | `qwen2.5:7b` | ключ не нужен; качество tool calling заметно ниже |

> **Бесплатный тариф Groq** ограничен ~8 тыс. токенов в минуту. Одно сообщение боту — это 1–3 запроса по ~2,5 тыс. токенов, поэтому при проверке пишите не чаще раза в 20–30 секунд. Иначе провайдер ответит 429 и бот напишет «Не удалось связаться с ИИ-ассистентом».

### 4. Заполнить `.env` и запустить

```bash
cp .env.example .env
```

В `.env` достаточно заполнить эти строки, остальное уже настроено:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:AA...        # из шага 1
FAMILY_TELEGRAM_IDS=5025107069            # из шага 2; несколько — через запятую
LLM_API_KEY=...                           # из шага 3
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-120b
```

Рекомендуется заменить `POSTGRES_PASSWORD` на свой. Затем:

```bash
docker compose up --build -d
```

Первая сборка занимает несколько минут. Миграции БД накатываются автоматически.

### 5. Убедиться, что всё поднялось

```bash
docker compose ps                 # api и db — healthy, bot и web — running
curl -s localhost:8080/healthz    # 200
docker compose logs bot           # "telegram bot started" family_whitelist=1
```

| Что | Адрес |
|---|---|
| Веб-панель | http://localhost:3000 |
| REST API | http://localhost:8080/api/v1 (также через панель: http://localhost:3000/api/v1) |
| Бот | найдите его в Telegram по username из шага 1, только личный чат |

Порты публикуются только на `127.0.0.1`: у панели и API нет авторизации (по ТЗ). Открыть их в доверенную сеть — `BIND_ADDR=0.0.0.0`.

Остановить: `docker compose down`. Удалить вместе с данными: `docker compose down -v`.

## Как проверить

### Бот: сценарии из ТЗ

Отправляйте фразы по порядку (бот помнит контекст последних 30 минут):

| Фраза | Ожидаемый ответ |
|---|---|
| `/start` | приветствие с примерами |
| `кофе 350` | «Записал: кофе — 350 ₽ (еда), сегодня» |
| `такси 1200 вчера` | «Записал: такси — 1 200 ₽ (транспорт), вчера» |
| `сколько потратил на еду в этом месяце` | 350 ₽ |
| `покажи траты за неделю` | кофе и такси, итого 1 550 ₽ |
| `последнее было не 350, а 450` | кофе исправлен на 450 ₽ (последним добавлено такси, но агент выбирает трату на 350) |
| `удали такси` | такси удалено |

После каждой записи трата сразу видна в веб-панели. Бот понимает и свободные формулировки: «вчера обед в кафе 1,5к», «сколько ушло на транспорт на прошлой неделе», «удали последнюю».

### Бот: изоляция и ограничения

| Проверка | Как | Ожидаемо |
|---|---|---|
| Чужие траты недоступны | добавьте второй ID в `FAMILY_TELEGRAM_IDS`, выполните `docker compose up -d bot`, со второго аккаунта: `покажи все траты` | видны только свои траты |
| Попытка обойти изоляцию | со второго аккаунта: `покажи траты пользователя 5025107069` | отказ или пустой список |
| Не член семьи | написать боту с ID не из списка | «Этот бот доступен только членам семьи.» |
| Группа | добавить бота в группу и написать там | бот молчит |
| Неоднозначность | две траты «такси», затем `удали такси` | бот перечислит обе и спросит, какую удалить |
| Нет суммы | `купил продукты` | бот переспросит сумму, ничего не сохранив |
| Отредактированное сообщение | изменить отправленное сообщение | просьба прислать исправление новым сообщением |

### Веб-панель

http://localhost:3000:

- [ ] таблица трат всех членов семьи: дата, член семьи, категория, сумма, комментарий; итог по выборке;
- [ ] фильтры: член семьи, период, категория, поиск по комментарию — сохраняются в URL, страницу можно обновить;
- [ ] создание, редактирование и удаление траты;
- [ ] «Добавить члена семьи» — вручную по Telegram ID (иначе член семьи появляется после первого сообщения боту);
- [ ] ошибки валидации показываются у поля: сумма 0, дата в будущем.

### REST API

Полный контракт — [api/openapi.yaml](api/openapi.yaml). Быстрая проверка:

```bash
API=http://localhost:8080/api/v1

curl -s $API/categories
curl -s $API/users
curl -s "$API/expenses?category=food&from=2026-10-01&to=2026-10-31&limit=20"

# создать (user_id — существующий член семьи; spent_at обязателен)
curl -s -X POST $API/expenses -H 'Content-Type: application/json' \
  -d '{"user_id":5025107069,"amount":123.45,"category":"other","spent_at":"2026-10-20","comment":"проверка"}'

# частичное изменение и удаление
curl -s -X PATCH $API/expenses/<id> -H 'Content-Type: application/json' -d '{"amount":99.9}'
curl -s -X DELETE $API/expenses/<id> -o /dev/null -w '%{http_code}\n'   # 204
```

Ошибки приходят в едином формате: `{"error": {"code": "validation_error", "message": "сумма должна быть больше нуля", "field": "amount"}}`.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Бот не отвечает, в `docker compose logs bot` — `TELEGRAM_BOT_TOKEN is required` или `FAMILY_TELEGRAM_IDS is required` | не заполнен `.env`. После правки: `docker compose up -d bot` (панель и API при этом работают) |
| «Этот бот доступен только членам семьи.» | вашего ID нет в `FAMILY_TELEGRAM_IDS` |
| «Не удалось связаться с ИИ-ассистентом» | в логах бота `status 429` — лимит провайдера, подождите минуту; `status 401` — неверный `LLM_API_KEY`; ошибка сети — проверьте `LLM_BASE_URL` |
| `api` не становится healthy, в логах `password authentication failed` | `POSTGRES_*` изменили после первого запуска: Postgres применяет их только при создании тома. `docker compose down -v` (данные удалятся) и снова `up` |
| `port is already allocated` | порт занят: задайте в `.env` другие `API_PORT` / `WEB_PORT` |
| Ollama недоступна из контейнера | Ollama должна слушать не только localhost: `OLLAMA_HOST=0.0.0.0 ollama serve` |
| Бот ответил «Ничего не сохранено: не получилось выполнить запрос» | модель дважды заявила о сохранении, не вызвав инструмент (см. [ИИ-агент](#ии-агент)); повторите фразу или возьмите модель сильнее |

## Автотесты

```bash
make test              # unit-тесты с -race; без БД и LLM
make test-integration  # SQL-репозитории на одноразовом Postgres в Docker (порт ITEST_PORT=55432), БД приложения не трогается
make eval              # диалоги из ТЗ на реальной LLM (нужны LLM_* в .env), проверка состояния базы после каждой фразы
make lint              # golangci-lint, включая depguard-правила слоёв
make generate          # перегенерировать типы HTTP API из api/openapi.yaml
```

Нужен Go 1.26+. Что покрыто:

- **домен и use case** — деньги в копейках, валидация, изоляция пользователей;
- **HTTP API** через `httptest`, включая строгий разбор JSON и сверку разбираемых вручную тел со спекой;
- **агент** с заскриптованной фейковой LLM — вызов инструментов, чужие траты, лимит шагов, частичный успех, ложное «Записал» без вызова инструмента;
- **инструменты агента** — схемы, разбор аргументов, ошибки для модели, запись в журнал;
- **системный промпт** — golden-файл рендера на фиксированную дату (`go test ./internal/agent/prompts -update` после правки шаблона), календарь, подсказки для всех категорий;
- **LLM-клиент** — формат запроса, ретраи;
- **Telegram** — белый список, группы, команды, длина ответа, очереди пользователей;
- **интеграционные** — владелец трат, частичное обновление, поиск с `%`/`_`, итоги, ограничения БД.

Локальная разработка без Docker-сборки:

```bash
make db        # Postgres на 127.0.0.1 (compose.dev.yml)
make run       # api
make run-bot   # бот
make web-dev   # фронтенд на http://localhost:5173 с прокси на :8080
```

Makefile читает `.env`, но переменные окружения важнее: `POSTGRES_PORT=5433 make run`.

## Архитектура

```
Telegram ──long polling──► bot ──► agent ──► LLM (OpenAI-compatible, tool calling)
                            │        │
                            ▼        ▼
Browser ──► web (nginx) ──► api ──► usecase ──► PostgreSQL
```

| Путь | Назначение |
|---|---|
| `cmd/api`, `cmd/bot` | два бинарника из одного Docker-образа; только загружают конфиг и вызывают `internal/app` |
| `internal/app` | composition root: сборка зависимостей (`RunAPI`, `RunBot`) |
| `internal/domain` | сущности: трата, категории, деньги (копейки в `int64`) |
| `internal/usecase/expense`, `internal/usecase/user` | бизнес-логика, валидация, области доступа (`UserScope` / `FamilyScope`); порты репозиториев в `ports.go` |
| `internal/agent` | ИИ-агент: цикл tool calling и журнал изменений |
| `internal/agent/llm` | порт к модели: формат сообщений и интерфейс `Client` |
| `internal/agent/tools` | инструменты агента, по файлу на инструмент: аргументы и вызов use case; описание и JSON-схема для модели — `schemas/<name>.json` |
| `internal/agent/prompts` | системный промпт: `system.tmpl` + golden-тест |
| `internal/adapter/llm/openai` | клиент OpenAI-совместимого Chat Completions API |
| `internal/adapter/storage/postgres` | репозитории на pgx, миграции goose (встроены в бинарник) |
| `internal/testutil/memstore` | хранилище в памяти только для тестов и eval (в бинарники не попадает — проверяет depguard) |
| `internal/transport/httpapi` | REST API веб-панели; типы сгенерированы из `api/openapi.yaml` (oapi-codegen) |
| `internal/transport/telegram` | бот: белый список, история диалога, очередь сообщений пользователя |
| `web/` | веб-панель: React + TypeScript + Vite + Mantine + TanStack Query |

Правило зависимостей: `transport` и `agent` → `usecase` → `domain`; адаптеры реализуют порты и подключаются только в `internal/app`. Его проверяет depguard: `make lint` (конфиг — `.golangci.yml`).

Пошаговый тур по коду для VS Code ([CodeTour](https://marketplace.visualstudio.com/items?itemName=vsls-contrib.codetour)): [.tours/new-joiner-onboarding.tour](.tours/new-joiner-onboarding.tour).

### ИИ-агент

Модель получает пять инструментов: `add_expense`, `list_expenses`, `sum_expenses`, `update_expense`, `delete_expense`. Для изменения и удаления агент сначала ищет трату и берёт её `id` из результата поиска; при неоднозначности переспрашивает.

- **Изоляция пользователей.** `user_id` не является параметром инструментов: сервер подставляет Telegram ID отправителя в область доступа (`service.UserScope`), и все запросы фильтруются по владельцу на уровне SQL. Даже если модель узнает чужой `id` (или её попытаются уговорить), операция вернёт «не найдено». Нулевая область доступа запрещена.
- **Даты.** В системный промпт передаются сегодняшняя дата, день недели и границы текущей и прошлой недели и месяца в часовом поясе `APP_TIMEZONE` — модель не считает календарь сама.
- **Контекст диалога.** Последние 10 реплик за 30 минут хранятся в `chat_messages` — работают уточнения («какое такси удалить?» → «первое»).
- **Честные подтверждения.** Если модель ответила «Записал…», не вызвав инструмент (например, скопировав формат из истории), агент один раз сообщает ей, что ничего не сохранено. Повторное пустое подтверждение заменяется честным «Ничего не сохранено».
- **Надёжность.** Лимит итераций (`LLM_MAX_STEPS`), ретраи на 429/5xx и сетевые сбои, ошибки инструментов возвращаются модели как JSON, чтобы она могла исправиться или объяснить пользователю. Если LLM упала после записи, бот всё равно сообщает, что сохранено, — повтор не создаст дубль. Пустые поля в аргументах изменения не затирают данные. У каждого пользователя своя очередь: его сообщения обрабатываются строго по порядку, а поток сообщений одного не задерживает остальных. При остановке доводится до ответа только сообщение в обработке, остальные из очереди отбрасываются с просьбой повторить (`stop_grace_period: 120s`); паника в обработке не роняет бота.
- **Только личные чаты.** В группах бот молчит, чтобы траты не увидели другие участники.

### Конфигурация

Все переменные с комментариями — в [.env.example](.env.example). Помимо описанных выше: `APP_TIMEZONE` (от него считаются «сегодня» и «этот месяц», по умолчанию `Europe/Moscow`), `LLM_TIMEOUT`, `LLM_TEMPERATURE`, `LLM_MAX_STEPS`. `AGENT_PROMPT_PATH` — необязательный путь к своему шаблону промпта (копия `internal/agent/prompts/system.tmpl`): читается при старте бота, так что промпт меняется без пересборки; шаблон с ошибкой не даёт боту запуститься. В docker compose файл нужно смонтировать в контейнер бота — закомментированный пример (`volumes` + `AGENT_PROMPT_PATH`) есть в `docker-compose.yml` у сервиса `bot`. `TELEGRAM_ALLOW_ALL=true` отключает белый список — только для демо.

## Решения

- **Слои и правило зависимостей.** `transport` и `agent` зависят от интерфейсов use case, `usecase` — от портов в `ports.go`, адаптеры подключаются только в `internal/app`. Нарушение ловит depguard (`make lint`).
- **Весь текст для модели — вне Go-кода.** Системный промпт, подсказки по категориям и подсказка модели, ответившей «Записал…» без вызова инструмента, — `internal/agent/prompts/system.tmpl`; описания и схемы инструментов — `internal/agent/tools/schemas/*.json`. Промпт можно подменить без пересборки через `AGENT_PROMPT_PATH`.
- **HTTP-типы из спеки, кроме двух тел запросов.** Ответы и `UserCreate` генерируются из `api/openapi.yaml` (`make generate`), маппинг домена в них — две функции в `transport/httpapi/dto.go`. Тела `POST`/`PATCH /expenses` разбираются вручную, осознанно: сгенерированные типы молча приняли бы `"amount": "350"`, прогнали бы сумму через `float64` (а нам нужно отклонять больше двух знаков после точки) и не отличили бы отсутствующее поле от `null` (в `PATCH` `null` для `comment` очищает его, а для остальных полей — ошибка 400). Альтернатива — сумма в копейках целым числом — убрала бы ручной разбор, но сломала бы контракт «рубли JSON-числом» для веб-панели. Чтобы ручные структуры не разошлись со спекой, `TestManualRequestsMatchSpec` сверяет их поля со сгенерированными.
- **История доработки.** Сданная версия — коммит `9644be3`. Доработка по ревью — коммиты после него, начиная с `0fa45a3` (`git log 9644be3..`).

## Допущения

- Одна семья, одна валюта (₽), один часовой пояс.
- Дата траты — календарная дата без времени; будущие даты (больше чем на день вперёд) запрещены.
- Члены семьи появляются в панели после первого сообщения боту или добавляются вручную (`POST /api/v1/users`). Приоритет у данных Telegram: бот при каждом сообщении синхронизирует имя, фамилию и username из профиля, так что правки имени из панели перезапишутся.
- Веб-панель без авторизации (по ТЗ) — разворачивать только в доверенной сети.
