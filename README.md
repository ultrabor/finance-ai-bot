# Finance AI Bot

Сервис учёта семейных расходов: член семьи пишет боту в Telegram «кофе 350» — ИИ-агент сам определяет сумму, категорию и дату и сохраняет трату. Глава семьи видит и редактирует траты всех в веб-панели.

Задание: [docs/test-task-expenses.md](docs/test-task-expenses.md) · паспорт проекта: [docs/PROJECT_PASSPORT.md](docs/PROJECT_PASSPORT.md) · REST API: [api/openapi.yaml](api/openapi.yaml)

## Быстрый старт

```bash
cp .env.example .env
# заполнить TELEGRAM_BOT_TOKEN (от @BotFather) и LLM_API_KEY / LLM_BASE_URL / LLM_MODEL
docker compose up --build
```

- Веб-панель: http://localhost:3000
- REST API: http://localhost:8080/api/v1 (и через панель по `/api/v1`)
- Бот: напишите ему в Telegram (только в личном чате)

Порты публикуются на `127.0.0.1`: панель и API без авторизации. Чтобы открыть их в доверенной сети, задайте `BIND_ADDR=0.0.0.0`.

Миграции накатываются автоматически при старте `api` и `bot`.

## Что умеет бот

| Фраза | Действие |
|---|---|
| кофе 350 | записать 350 ₽ в «еду» на сегодня |
| такси 1200 вчера | записать 1 200 ₽ в «транспорт» на вчера |
| сколько потратил на еду в этом месяце | сумма за период по категории |
| покажи траты за неделю | список трат за последние 7 дней |
| последнее было не 350, а 450 | найти трату и исправить сумму |
| удали такси | найти и удалить; если подходит несколько — переспросит |

Без кнопок и команд (кроме служебного `/start`). Каждый пользователь видит только свои траты.

## Архитектура

```
Telegram ──long polling──► bot ──► agent ──► LLM (OpenAI-compatible, tool calling)
                            │        │
                            ▼        ▼
Browser ──► web (nginx) ──► api ──► service ──► PostgreSQL
```

| Путь | Назначение |
|---|---|
| `cmd/api`, `cmd/bot` | два бинарника из одного Docker-образа |
| `internal/domain` | сущности: трата, категории, деньги (копейки в `int64`) |
| `internal/service` | бизнес-логика, валидация, области доступа (`UserScope` / `FamilyScope`) |
| `internal/storage/postgres` | репозитории на pgx, миграции goose (встроены в бинарник) |
| `internal/storage/memory` | хранилище в памяти для тестов и eval |
| `internal/httpapi` | REST API веб-панели |
| `internal/llm` | клиент OpenAI-совместимого Chat Completions API |
| `internal/agent` | ИИ-агент: системный промпт, инструменты, цикл tool calling |
| `internal/telegram` | адаптер бота: белый список, история диалога, очередь сообщений пользователя |
| `web/` | веб-панель: React + TypeScript + Vite + Mantine + TanStack Query |

### ИИ-агент

Модель получает пять инструментов: `add_expense`, `list_expenses`, `sum_expenses`, `update_expense`, `delete_expense`. Для изменения и удаления агент сначала ищет трату и берёт её `id` из результата поиска; при неоднозначности переспрашивает.

- **Изоляция пользователей.** `user_id` не является параметром инструментов: сервер подставляет Telegram ID отправителя в область доступа (`service.UserScope`), и все запросы фильтруются по владельцу на уровне SQL. Даже если модель узнает чужой `id` (или её попытаются уговорить), операция вернёт «не найдено». Нулевая область доступа запрещена.
- **Даты.** В системный промпт передаются сегодняшняя дата, день недели и границы текущей и прошлой недели и месяца в часовом поясе `APP_TIMEZONE` — модель не считает календарь сама.
- **Контекст диалога.** Последние 10 реплик за 30 минут хранятся в `chat_messages` — работают уточнения («какое такси удалить?» → «первое»).
- **Надёжность.** Лимит итераций (`LLM_MAX_STEPS`), ретраи на 429/5xx и сетевые сбои, ошибки инструментов возвращаются модели как JSON, чтобы она могла исправиться или объяснить пользователю. Если LLM упала после записи, бот всё равно сообщает, что сохранено, — повтор не создаст дубль. Пустые поля в аргументах изменения не затирают данные. У каждого пользователя своя очередь: его сообщения обрабатываются строго по порядку, а поток сообщений одного не задерживает остальных. При остановке доводится до ответа только сообщение в обработке, остальные из очереди отбрасываются с просьбой повторить (`stop_grace_period: 120s`); паника в обработке не роняет бота.
- **Только личные чаты.** В группах бот молчит, чтобы траты не увидели другие участники.

## Конфигурация LLM

Любой провайдер с OpenAI-совместимым `/chat/completions` и поддержкой tool calling:

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` (пример) |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-haiku-4.5` |
| Ollama (локально) | `http://host.docker.internal:11434/v1` | `qwen2.5:7b` |

Остальные переменные — в [.env.example](.env.example). `FAMILY_TELEGRAM_IDS` (белый список членов семьи) обязателен; для демо без него — `TELEGRAM_ALLOW_ALL=true`.

## Разработка

```bash
make test        # go test -race ./...
make db          # Postgres с портом на 127.0.0.1 (compose.dev.yml) для make run / run-bot
make test-integration  # SQL-репозитории на одноразовом Postgres в Docker
make eval        # сценарии из ТЗ против реальной LLM (нужны LLM_* в .env)
make run         # api локально (после make db)
make run-bot     # бот локально
make web-dev     # фронтенд на http://localhost:5173 с прокси на :8080
```

Makefile читает `.env`, но переменные окружения и аргументы make важнее: `POSTGRES_PORT=5433 make run` или `make run POSTGRES_PORT=5433`. Интеграционные тесты поднимают отдельный контейнер Postgres (порт `ITEST_PORT`, по умолчанию 55432) и удаляют его после прогона — данные приложения не затрагиваются.

Тесты: доменные (деньги), сервисные (изоляция, валидация), HTTP API через `httptest` (включая строгий разбор JSON), агент с заскриптованной фейковой LLM (вызов инструментов, чужие траты, лимит шагов, частичный успех, календарь в промпте), LLM-клиент (формат запроса, ретраи), Telegram-обработчик (белый список, группы, команды, длина ответа) и очереди пользователей. Интеграционные тесты (`make test-integration`) проверяют SQL: владельца трат, частичное обновление, поиск с `%`/`_`, итоги, ограничения БД. `make eval` прогоняет диалог из ТЗ на настоящей модели и проверяет состояние базы после каждой фразы.

## Допущения

- Одна семья, одна валюта (₽), один часовой пояс.
- Дата траты — календарная дата без времени; будущие даты (больше чем на день вперёд) запрещены.
- Члены семьи появляются в панели после первого сообщения боту или добавляются вручную (`POST /api/v1/users`). Приоритет у данных Telegram: бот при каждом сообщении синхронизирует имя, фамилию и username из профиля, так что правки имени из панели перезапишутся.
- Веб-панель без авторизации (по ТЗ) — разворачивать только в доверенной сети.
